# Examples

## `upx-sample/`

Output of a real run against the synthetic fixture generated by `scripts/make-fixtures.mjs`
(a hand-built PE32 with a `UPX0` virtual-only section, a `pushad` stub ending in
`push 0x401000 ; ret`, a TLS callback, `int 2d` / `icebp` anti-debug bytes, and a deliberate
stale import-descriptor array).

Reproduce:

```bash
npm run fixtures
node bin/lbi.mjs zxwn analyze fixtures/packed-sample.exe --out examples/upx-sample
```

Contents:

| File | What it is |
|---|---|
| `report.md` | human-readable report (Chinese by default), 9 sections + per-section evidence chain |
| `analysis.json` | full machine-readable result (187 KB) |
| `scripts/recover.x64dbg.txt` | breakpoints for TLS callback, entry, OEP candidates, indirect transfers |
| `scripts/recover.gdb.txt` / `recover.windbg.txt` | same plan for other debuggers |
| `scripts/recover.frida.js` | runtime script: PEB patch, API interception, RWX watch, OEP dump |
| `scripts/rebuild.scylla.txt` | IAT rebuild command |
| `scripts/patches.txt` | directly applicable patch list (offset → bytes) |

The fixture contains no malicious code; it exists only to make the analysis path reproducible.
